# 12. Adopt tmux for terminal splits

Date: 2026-11-06

## Status

Accepted

## Context

Claude Code agent sessions run for days. Ghostty splits and tabs belong to the Ghostty window, so closing the window ends every process in it, including a running agent. Panes that outlive the window need a terminal multiplexer.

The keys must stay as they are. The `cmd` layer already drives splits, tabs, and pane navigation, and `Ctrl+h/j/k/l` already crosses Neovim splits. Replacing Ghostty splits must not change what is typed.

## Decision

tmux becomes the only terminal split and window system. Ghostty's own split and tab actions are removed from `ghostty/.config/ghostty/config`, and its built-in split and tab keybindings are unbound, so two split systems are never active at once.

Sessions follow the project. `zsh/.zshrc` runs `tmux new-session -A` with a name taken from the current folder, or `home` in the home folder, but only outside tmux and only when `TERM_PROGRAM` is `ghostty`. Ghostty's `command` option stays unused, so shell integration keeps working. `sesh` is the picker, opened on prefix `P` inside a popup that lists sessions and the directories under `~/code`. `tmux` and `sesh` are added to the `Brewfile`.

Ghostty translates the `cmd` keys into tmux commands with `text:` bindings: `cmd+d` and `cmd+shift+d` split, `cmd+shift+e` evens out panes, `cmd+t` opens a window, `cmd+w` closes a pane, `cmd+1` to `cmd+9` select windows, and `cmd+p` opens the picker. `cmd+h/j/k/l` send `Ctrl+h/j/k/l`. `cmd+n` still opens a Ghostty window, and `cmd+shift+w` still closes one, which detaches tmux and leaves the session running.

`mrjones2014/smart-splits.nvim`, pinned to `v2.1.1-final`, makes `Ctrl+h/j/k/l` and `Ctrl+arrows` work across Neovim splits and tmux panes, and stops at the edge instead of wrapping. The matching tmux bindings are in `tmux/.config/tmux/tmux.conf` and test the `@pane-is-vim` pane option. The plugin cap in [ADR 0011](0011-manage-neovim-plugins-with-vim-pack.md) rises from 35 to 36 for this plugin.

The AeroSpace focus gesture, `alt+shift+h/j/k/l`, walks four levels in order: the Neovim split, the tmux pane, the AeroSpace window, the display. `aerospace/.config/aerospace/scripts/focus.sh` handles the tmux step only when Ghostty is the focused application, and skips it when the pane is zoomed or at the edge in that direction. tmux `client-focus-in` and `client-focus-out` hooks record the focused client in a state file, so the script finds the right tmux client with several Ghostty windows open and falls through to AeroSpace when no client has focus.

The tmux configuration is settings only, with no plugin manager. The status line uses Carbonfox, vendored from the `extra/carbonfox/carbonfox.tmux` file generated by nightfox.nvim, with its MIT licence kept next to it as `LICENSE-nightfox`, and the `#{prefix_highlight}` reference removed since no plugin provides it. The `make check-tmux`, `make check-focus`, and `make check-ghostty` targets test the tmux settings, the focus script, and the Ghostty bindings.

## Consequences

Panes, windows, and the agents in them survive closing Ghostty. Windows restored by Ghostty attach to the session for their folder.

Nothing is restored after a reboot, since tmux-resurrect and tmux-continuum are not installed. Conversations are reopened by hand with `claude --continue` or `claude --resume`. The plugins can be added later if the loss is felt.

Ghostty's notify-on-command-finish is lost inside tmux. The loss is accepted.

A literal `Ctrl+h`, `Ctrl+j`, `Ctrl+k`, or `Ctrl+l` typed in a shell pane moves between panes instead of reaching the shell. Prefix followed by the same key sends it through. The Backspace key is unaffected.

Claude Code flickers more in fullscreen mode inside tmux, as its own documentation states.

smart-splits is held on the frozen v2 release, which talks to tmux directly. Moving to v3 needs a separate backend plugin, which would raise the plugin cap to 37.

The Carbonfox tmux theme is a copy of generated output and does not follow nightfox.nvim updates. Refreshing it means regenerating the file and reapplying the `prefix_highlight` removal.
